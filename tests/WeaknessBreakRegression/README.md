# 弱点破坏后的插入突刺回归

在仓库根目录运行：

```bash
python3 tools/test_weakness_break.py
```

需要 Python 3 与 .NET 9 SDK；SDK 不在 PATH 时使用 `--dotnet /path/to/dotnet`。进程退出码非零表示检查失败。

项目直接链接 `src/Monsters/ImperialVanguard.cs` 和 `src/Powers/WeaknessBreakPower.cs`。运行脚本从当前 `FlareMonster.cs` 提取 `DeadlyValue`、`ToughValue`、`Machine` 与 `Build`，将原始方法编译进测试项目，避免在测试中另外抄写数值映射或起手选择。测试先从生命变化调用 `AfterCurrentHpChanged`，确认生产代码调用了击晕命令并指定 `THRUST_MOVE`，随后执行生产突刺委托与生产恢复分支。

18 项行为检查覆盖：

- A0/A8 使用基础突刺 19、活力 10；A9/A10 使用基础突刺 20、活力 15。分别在远射、战意待执行时触发，断言意图与实际攻击参数一致、活力被消耗、只插入一次突刺，随后续接原有循环。
- 单阈值突刺 29/35；一次伤害或同一击晕期间跨越两个阈值，活力合计 20/30、突刺 39/50；首轮突刺完成后再次跨过第二阈值，可以再次触发。已有 2 力量的 A10 突刺为 37。
- HP 阈值按实际最大生命向下取整，检查 133/137/140/277 HP 的边界与血条标记；治疗不重置阈值；非自身生命变化、非负变化、死亡及其他怪物均不触发；命令重入不会重复发放奖励。

脚本还检查设计总览表与「沉默的屠夫」详细描述中的 19/20。原开局模拟保持玩家不攻击的统计口径，仍独立运行：

```bash
python3 docs/tools/opening_sim.py
```

`GameApiDoubles.cs` 替换外部 STS2、Godot 与 RitsuLib API。它建模 A8/A9 分界、击晕排程、力量/活力伤害修正与活力消耗，并记录生产代码发出的命令；格挡与视觉调用只提供编译所需接口。完整模组构建仍需要真实游戏程序集与 RitsuLib，替身测试无法验证这些外部接口的兼容性。

真实游戏仍需核实：击晕后的回合排程、伤害与意图显示中的原版修正、反伤在敌方出手期间触发、血条表现、突刺动画/音效，以及联机同步。
